# Flow Steps — расширение Qwen Code

Два скилла ведут пользователя по YAML-процессу: `/flow-steps:fs-run` обрабатывает
один узел, `/flow-steps:fs-confirm` фиксирует принятие рабочего шага. Решение о качестве принимает
пользователь. Состояние сохраняется до работы, поэтому следующий шаг можно
выполнить в новой сессии.

## Установка

Нужны Python **3.11 или новее**, Git и актуальный Qwen Code с поддержкой скиллов
расширений. Дополнительные Python-пакеты не нужны: PyYAML включён в поставку.
Расширение не запускает серверы, не требует API-ключей, сборки или npm-зависимостей.

Установи **папку с `qwen-extension.json`** из терминала. Например, из корня этого
репозитория:

```text
qwen extensions install ./flow-steps
```

Абсолютный путь также поддерживается; пути с пробелами заключай в кавычки.
Внутри интерактивного Qwen Code можно выполнить:

```text
/extensions install /absolute/path/to/flow-steps
```

Либо установи подготовленный ZIP без распаковки:

```text
qwen extensions install ./dist/flow-steps-1.0.0.zip
```

По умолчанию расширение включается для пользователя. Чтобы включить его только
в нужном проекте, запусти установку из этого проекта с `--scope project`.

Qwen копирует расширение в свой каталог установки. Обновление из того же источника:

```text
qwen extensions update flow-steps
```

После установки из терминала перезапусти активную сессию Qwen. Проверь расширение
через `/extensions`, а скиллы — через `/skills`. Зарегистрированные имена:

```text
/flow-steps:fs-run
/flow-steps:fs-confirm
```

Префикс `flow-steps:` добавляет Qwen Code по имени расширения. Это не отдельные
пользовательские алиасы `/fs-run` и `/fs-confirm`. В `SKILL.md` остаются исходные
имена `fs-run` и `fs-confirm`. Если раньше ты скопировал отдельные скиллы в
`~/.qwen/skills/` или `.qwen/skills/`, старые копии можно убрать после проверки
расширения, чтобы не путать два варианта установки. Состояние `.flows/` сохраняется.

## Структура расширения

```text
flow-steps/
  qwen-extension.json
  README.md
  skills/
    fs-run/
      SKILL.md
      scripts/flow.py
      scripts/vendor/
      references/
      templates/example-flow.yaml
    fs-confirm/
      SKILL.md
```

Манифест указывает `skills: "skills"`. Оба скилла используют один движок,
расположенный внутри расширения, а не в рабочем проекте. OpenAI-метаданных нет.

## Подготовка проекта

1. Работай в Git-репозитории. Скопируй `skills/fs-run/templates/example-flow.yaml` из расширения в
   `flows/feature.yaml` и адаптируй шаги. В примере нет зависимости от сторонних
   скиллов; поле `skill` можно добавить позже.
2. Добавь `/.flows/` в `.gitignore`. Закоммить настройку и определение флоу.
   Первый рабочий шаг требует чистого дерева.
3. Вызови `/flow-steps:fs-run`. После результата проверь его и вызови `/flow-steps:fs-confirm`.
4. Начни новую сессию для следующего рабочего шага и снова вызови `/flow-steps:fs-run`.

После развилки всегда нужен новый `/flow-steps:fs-run`, даже если дальше ещё одна развилка.
Повторные попытки не откатывают файлы. Все изменения рабочего дерева во время
шага должны относиться к этому шагу: подтверждение коммитит их все.

Если у шага нет `commitMessage`, `/flow-steps:fs-confirm` при наличии диффа спрашивает
сообщение для одной попытки. Оно не сохраняется в стейте. После неудачной попытки
сообщение запрашивается заново. Если диффа нет, вопрос и коммит пропускаются.

## Разработка

Тесты и инструмент обновления зависимости лежат вне устанавливаемых скиллов,
в корне исходного репозитория:

```text
python -B -m unittest discover -s tests -v
python tools/build_extension.py
python tools/vendor_pyyaml.py
```

`build_extension.py` без сети собирает `dist/flow-steps-<version>.zip` из каталога
расширения. Манифест находится в корне архива; тесты, инструменты разработки,
кеш Python и состояние прогонов в архив не включаются.

`vendor_pyyaml.py` нужен только сопровождающему поставку и использует сеть. Он скачивает
закреплённый исходный архив PyYAML, проверяет SHA-256, копирует Python-файлы и
лицензию и записывает provenance. При обычном использовании сеть не нужна.

Скиллы уменьшают требования к памяти модели, но не могут гарантировать исполнение
инструкций самой моделью. Движок контролирует свои операции; запуск задания
агентом разрешён только после ответа `execute_step` с `state_saved: true`.
