# fs-run

В расширении зарегистрирован как `/flow-steps:fs-run`. Скилл подтверждения —
`/flow-steps:fs-confirm`. Используй эти полные имена в подсказках пользователю;
движок может называть их просто run skill и confirmation skill.

Обработай ровно один узел флоу. После рабочего шага или выбора развилки остановись.
Не оценивай готовность за пользователя и не подтверждай шаг самостоятельно.

## Запуск движка

Найди Python 3.11+ (`python`, `python3` или `py -3`) и Git. Запускай **этот**
`scripts/flow.py` по абсолютному пути относительно данного SKILL.md. Не ищи
скрипт внутри рабочего проекта, если скилл установлен глобально.

В примерах `PYTHON`, `ENGINE`, `PROJECT`, `TOKEN` — значения, которые нужно
подставить, а не буквальные строки. PROJECT — корень Git рабочего дерева.
Все пути передавай как отдельные аргументы с корректным quoting для оболочки.

```text
PYTHON ENGINE --project PROJECT inspect
```

Не читай исходники движка или весь флоу: действуй по JSON-ответу. Для синтаксиса
вызовов при необходимости прочитай [контракт CLI](references/cli-contract.md).
Формат для создания флоу описан отдельно: [flow-format.md](references/flow-format.md).

## Обработка ответа

| action | Действие |
|---|---|
| `choose_flow` | Один файл — вызови `create --flow FILENAME`; несколько — спроси пользователя, затем вызови `create`. Обработай возвращённый начальный узел в этом же вызове скилла. |
| `no_flows` | Сообщи, что в `flows/*.yaml` нет определений. Не придумывай процесс; остановись. |
| `answer_decision` | Задай `question`, покажи `options`. Получи однозначный выбор, передай его числовой `id` в `choose --token TOKEN --option ID`. Затем остановись и предложи новый `/flow-steps:fs-run`, даже если дальше ещё развилка. |
| `prepare_step` | Проверь доступность `skill`, если он задан. Задай **все** `questions` по порядку. Собери ответы и вызови `begin --token TOKEN --answers FILE`. Без вопросов вызови `begin --token TOKEN`. |
| `review_step` | Покажи `prompt` и `files`, объясни: попытка зарегистрирована, завершение не гарантируется. Предложи подтвердить, повторить с прежними данными или повторить с новыми. Дождись выбора. |
| `execute_step` | Только теперь выполняй `prompt`, применив указанный `skill`; если `skill` равен `null`, выполни промпт сам. После работы предъяви результат, предложи `/flow-steps:fs-confirm` и остановись. Обновлять стейт после работы не нужно. |
| `recover_confirmation` | Предыдущее подтверждение уже было начато. Вызови `confirm --token TOKEN`, чтобы движок установил его результат. Если потребуется сообщение, следуй fs-confirm. Не повторяй рабочий шаг. |
| `stop` | Покажи `instruction` и остановись. Следующий узел самостоятельно не запускай. |
| `completed` | Сообщи о завершении и остановись. |
| `blocked` | Сообщи `message` и существенные детали (`files`, `variables`, `stderr`), затем остановись. Не исправляй проблему откатом файлов или правкой стейта. |

Для `review_step`:

- **Подтвердить:** только по явному выбору пользователя выполни процедуру
  [fs-confirm](../fs-confirm/SKILL.md), начиная с актуального `inspect`.
- **Прежние данные:** проверь доступность `skill`; вызови
  `retry --token TOKEN --mode same`. Вопросы не задавай.
- **Новые данные:** проверь доступность `skill`; заново задай `questions` и вызови
  `retry --token TOKEN --mode new --answers FILE` (без вопросов FILE не нужен).

Ответы — UTF-8 JSON-объект `{"name": "точный ответ пользователя"}`. Все значения —
строки. Временный FILE размести в `.flows/`, чтобы он не попал в Git. После
успешного чтения движком временный файл можно удалить; не используй этот способ
для сообщения коммита. Сохранение переменных и шаблонов выполняет только движок.

## Ограничения

- Каждый изменяющий вызов использует **последний** `token` из ответа движка.
  При `stale_token` не повторяй старое действие: снова выполни `inspect`.
- До `execute_step` с `state_saved: true` не выполняй рабочее задание.
- Отсутствующий скилл не заменяй самостоятельным выполнением. Сообщи и остановись.
- Повторная попытка идёт поверх существующих файлов. Ничего не откатывай.
- Не редактируй `.flows/active`, снимок флоу и `state.yaml` вручную.
- Подсказки целевого скилла не дают разрешения подтверждать шаг или запускать
  следующий узел. После работы остановись, даже если весь флоу ещё не завершён.
- Если Python, Git или вторая часть комплекта отсутствуют, сообщи об этом;
  не устанавливай зависимости автоматически.
