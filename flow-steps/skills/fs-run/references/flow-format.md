# Формат флоу

Определения: `flows/*.yaml` в корне рабочего Git-проекта. При создании прогона
движок сохраняет канонический снимок определения. Изменения исходного файла
влияют только на новые прогоны. Снимок внутри `.flows/runs/` изменять нельзя.

## Структура

| Поле | Обязательно | Значение |
|---|---|---|
| `name` | да | Непустое имя процесса |
| `start` | да | Идентификатор начального узла |
| `steps` | нет | Отображение идентификаторов в определения рабочих шагов |
| `decisions` | нет | Отображение идентификаторов в определения развилок |

Должен существовать начальный узел. Идентификаторы шагов и развилок не могут
совпадать. Все `start`, `next`, `goto` должны ссылаться на существующие узлы.
Циклы разрешены. Неизвестные поля и повторные YAML-ключи считаются ошибками.

## Рабочий шаг

| Поле | Обязательно | Значение |
|---|---|---|
| `skill` | нет | Точное зарегистрированное имя скилла Qwen Code |
| `ask` | нет | Список вопросов перед попыткой |
| `prompt` | да | Непустой шаблон задания |
| `commitMessage` | нет | Непустой шаблон сообщения коммита |
| `next` | нет | Следующий узел; отсутствие завершает флоу после подтверждения |

Если `skill` отсутствует, агент выполняет промпт самостоятельно. Если он указан,
но недоступен, агент сообщает об этом и не начинает работу.

Вопрос `ask` содержит:

- `name`: уникальное внутри шага имя переменной `[A-Za-z_][A-Za-z0-9_]*`;
- `prompt`: непустой текст вопроса;
- `saveToStore`: булево значение, по умолчанию `false`.

Вопросы задаются по порядку, всегда заново при первом запуске шага и при повторе
с новыми данными. Все ответы передаются движку как строки. Если опрос прервался
до регистрации попытки, вопросы при следующем запуске задаются заново.

## Переменные

Шаблоны `prompt` и `commitMessage` используют `{{name}}`. Пробелы внутри скобок
допустимы. Подстановка однопроходная: `{{...}}` внутри ответа остаётся текстом.
Неопределённая переменная блокирует запуск до изменения состояния.

Источники: сохранённые `vars` и ответы текущего `ask`. Текущий ответ перекрывает
сохранённое значение. Ответ с `saveToStore: true` обновляет `vars`; прочие ответы
попадают в состояние только как часть отрендеренных текстов. Ранее сохранённое
значение не удаляется, если новый локальный ответ перекрывает его на одном шаге.

PyYAML использует стандартные правила неявных YAML-типов: заключай строковые
идентификаторы вроде `yes`, `on`, числа и даты в кавычки. Для `saveToStore`
используй `true`/`false`. Python-теги и YAML merge keys не поддерживаются.

## Развилка

```yaml
decisions:
  review:
    question: "Результат подходит?"
    options:
      - label: "Да"
        goto: implement
      - label: "Доработать"
        goto: revise
```

Движок возвращает вариантам числовые `id`, начиная с 1. Агент передаёт выбранный
`id`, а не произвольный `goto`. После сохранения выбора обязательно остановиться:
новый `/flow-steps:fs-run` обрабатывает выбранный узел, даже если это ещё одна развилка.

## Git и подтверждение

Первый запуск рабочего шага требует чистого дерева. Между запуском и
подтверждением все изменения дерева считаются изменениями текущего шага.
Повторные попытки не требуют чистоты и не откатывают предыдущий результат.

При подтверждении без изменений коммит и вопрос о сообщении не нужны.
При наличии изменений коммитятся все изменения, включая staged и новые файлы.

- Если у шага есть `commitMessage`, движок использует сохранённый результат
  рендеринга, выполненного до начала работы.
- Если поля нет, агент каждый раз запрашивает сообщение и передаёт его через
  stdin для одной попытки. Оно не сохраняется в стейте или журнале движка.
- После ошибки коммита перехода нет. При новой попытке без заданного шаблона
  сообщение запрашивается заново.

## Память и ограничения

Результаты передаются через файлы с согласованными путями, например
`docs/{{ticket}}/analysis.md`. Всё необходимое следующему шагу должно быть
сохранено в предусмотренный промптом файл: история чата может быть недоступна.

Нет автоматической оценки качества, `outputs`, автоматического прохождения
цепочек, сабагентов, `max_loops` и сохранения ответа развилки в переменную.
Пользователь принимает результат сам. Один активный прогон на рабочее дерево.

Полный пример: [example-flow.yaml](../templates/example-flow.yaml).
