# fs-confirm

В расширении зарегистрирован как `/flow-steps:fs-confirm`. Скилл запуска —
`/flow-steps:fs-run`. Используй эти полные имена в подсказках пользователю.

Подтверждение выполняется только по явному решению пользователя. Вызов
`/flow-steps:fs-confirm` является таким решением; дополнительно подтверждать его не нужно.
Качество результата не оценивай. Рабочий шаг заново не выполняй.

## Движок

Используй Python 3.11+ и общий `../fs-run/scripts/flow.py` относительно данного
SKILL.md. Оба скилла должны быть установлены рядом. Передавай абсолютный путь
к движку и корень рабочего Git-проекта. `PYTHON`, `ENGINE`, `PROJECT`, `TOKEN`
ниже обозначают подставляемые значения.

```text
PYTHON ENGINE --project PROJECT inspect
PYTHON ENGINE --project PROJECT confirm --token TOKEN
```

Возьми TOKEN из актуального `inspect`. При `review_step` или
`recover_confirmation` вызови `confirm`. При незапущенном шаге, развилке или
отсутствии прогона скажи, что сначала нужен `/flow-steps:fs-run`; не создавай прогон и не
обрабатывай узел. При `blocked` объясни ошибку и остановись.

## Ответ confirm

| action | Действие |
|---|---|
| `ask_commit_message` | Спроси непустое сообщение коммита и дождись ответа. Повтори `confirm --token TOKEN --message-stdin`, передав текст через stdin. Используй token из **этого** ответа. |
| `stop` | Сообщи о подтверждении и предложи `/flow-steps:fs-run`. Для следующего рабочего шага рекомендуй новую сессию. Остановись. |
| `completed` | Сообщи о завершении флоу. Остановись. |
| `blocked` | Объясни ошибку. Не меняй стейт, не выполняй переход и не делай коммит вручную. |

## Разовое сообщение коммита

- Запрашивай сообщение только после `ask_commit_message`: если изменений нет,
  либо сообщение задано самим шагом, движок выполнит нужное действие без вопроса.
- Передавай ответ только в stdin текущей команды. Не помещай его в файл,
  `state.yaml`, переменные прогона или аргумент командной строки.
- Если инструмент позволяет подать stdin, используй его. Иначе используй
  буквальный here-document/here-string и pipe с UTF-8. Не допускай подстановки
  `$()`, обратных кавычек или переменных внутри текста пользователя.
- Сообщение действует для одной попытки. При новой попытке подтверждения,
  включая ошибку коммита или новую сессию, снова начни с `inspect` и `confirm`
  **без** `--message-stdin`. Если движок снова запросит сообщение, задай вопрос
  заново, даже если прежний ответ ещё виден в чате.
- Git сохраняет сообщение как метаданные коммита. Сам движок не сохраняет его
  для последующих подтверждений.

Всю работу с Git и переходом выполняет движок. Не отключай проверки Git,
не обходи хуки, не откатывай файлы и не запускай следующий узел.
